## 1. 产品愿景与一句话定位

### 1.1 愿景

让每一位华语基督徒，每天都能在安静中领受一句从圣经而来的话语，并以可保存、可分享的美图形式，把属灵默想带进日常与社群。

### 1.2 一句话定位

**「金句日」是每日自动生成一张安静、庄重、属灵深度兼备的圣经金句图片 App，帮助人停下来，安静在神面前。**

### 1.3 不是什么

- 不是社交网络、不是教会管理系统  
- 不是以 AI 聊天为中心的产品（AI 对话为后期扩展）  
- 不是廉价「励志鸡汤图」生成器  
- 不追求商业广告感、网红滤镜感、过度符号化宗教图像

## 2. 目标用户画像（3 个）

### 画像 A：安静默想型 — 「晨更的小美」

| 维度 | 描述 |
|------|------|
| 年龄 | 28–45 |
| 场景 | 清晨 10–15 分钟灵修 |
| 痛点 | 想专注经文，却被信息流打断；自己做图太费时 |
| 动机 | 安静、默想、把经文存在手机里反复读 |
| 关键行为 | 打开 App → 看今日金句 → 静默片刻 → 可选保存 |

### 画像 B：分享见证型 — 「团契的阿华」

| 维度 | 描述 |
|------|------|
| 年龄 | 22–40 |
| 场景 | 微信/Instagram 故事、小组群 |
| 痛点 | 找到「好看又正统」的经文图很难；担心误用版权或不准确译本 |
| 动机 | 分享时既美又属灵、不尴尬、不商业 |
| 关键行为 | 打开 → 今日金句 → 一键分享 → 偶尔切换主题/尺寸 |

### 画像 C：长期养成型 — 「读经的建中」

| 维度 | 描述 |
|------|------|
| 年龄 | 35–60 |
| 场景 | 连续打卡、收藏金句、回顾历史 |
| 痛点 | 碎片化阅读缺乏节奏；希望有「每日一句」的稳定节奏 |
| 动机 | 属灵习惯、收藏、按主题回顾（平安、盼望等） |
| 关键行为 | 推送提醒 → 打开 → 收藏 → 翻历史 → 改偏好（译本/主题） |

## 3. MVP 功能列表（MoSCoW）

### 3.1 Must（必须有）

| ID | 功能 | 说明 |
|----|------|------|
| M1 | 今日金句 | 每日固定一条（按用户时区/日期），展示经文 + 出处 + 译本 |
| M2 | 金句图片 | 自动生成高质量图：AI/预设背景 + Canvas 精准叠字 |
| M3 | 三种尺寸 | 1080×1920、1080×1080、可选 1920×1080 |
| M4 | 分享/保存 | Web Share API + 下载 PNG |
| M5 | 历史列表 | 本地至少保存近 30 天生成记录 |
| M6 | 基础设置 | 译本（默认和合本 CUV）、主题、通知开关（PWA 能力内） |
| M7 | 离线可读 | 今日与近期历史可本地缓存（PWA） |
| M8 | 每日生成管道 | 定时任务生成「全站当日金句」资产（或用户打开时确定性生成） |

### 3.2 Should（应该有）

| ID | 功能 | 说明 |
|----|------|------|
| S1 | 多版式模板 | 居中 / 上下 / 左右 / 竖排 |
| S2 | 主题系统 | 至少 3 套视觉主题（黎明、静夜、旷野） |
| S3 | 收藏 | 用户收藏金句与图片 |
| S4 | 经文来源可追溯 | 显示出处、译本、生成日期 |
| S5 | 情绪/节期标签 | 如「安慰」「盼望」（内容元数据，非鸡汤） |

### 3.3 Could（可以有，MVP 后）

| ID | 功能 | 说明 |
|----|------|------|
| C1 | 用户账号（Supabase Auth） | 跨设备同步收藏与偏好 |
| C2 | 推送（Web Push） | 每日晨间提醒 |
| C3 | 自定义经文 | 用户输入章节生成图 |
| C4 | AI 默想短文 | 基于经文的简短默想（需神学审核策略） |
| C5 | 社群墙 | 匿名/具名分享（强克制） |
| C6 | 多译本 | NVI、ESV 等对照 |
| C7 | Flutter 客户端 | 复用 API 与生成管道 |

### 3.4 Won't（本期不做）

- 付费墙、广告 SDK  
- UGC 随意上传背景图（版权与调性风险）  
- 复杂社交关注/私信  
- 自动解经视频

## 4. 用户核心使用流程（每日打开路径）

```
启动 App（PWA / 浏览器）
    │
    ├─ 有推送？──► 点击通知 ──► 直达「今日」
    │
    ▼
【今日】页（默认首页）
    │  展示：背景金句大图 + 经文正文 + 出处/译本/日期
    │
    ├─ 静默阅读（主路径，无强制交互）
    │
    ├─ [保存图片] → 下载 PNG
    ├─ [分享] → 系统分享 / 复制图片
    ├─ [换版式] → 同经文切换模板（不换经文）
    ├─ [收藏] → 写入 Collection
    │
    ├─ 历史 → 按日浏览过往金句
    └─ 设置 → 主题 / 译本偏好 / 通知
```

### 4.1 关键路径原则

1. **3 秒内看到经文**（图可渐进加载）  
2. 主按钮不超过 2 个：保存、分享  
3. 不做弹窗广告、不做「再看一条」信息流上瘾设计  
4. 每日经文对同一用户同一天保持稳定（可复现）

## 5. 视觉与属灵调性要求

| 维度 | 要求 |
|------|------|
| 整体 | 极简、庄重、温暖、留白充足 |
| 色彩 | 低饱和：米白、雾灰、暮蓝、柔和绿；点缀可用暗金，克制 |
| 字体 | 中文：思源宋体（经文）/ 思源黑体（UI）；英文：衬线（如 Source Serif） |
| 图像 | 自然、抽象光影、古典油画质感、宁静；**禁止**清晰人脸、夸张十字架符号堆砌、商业海报感 |
| 文案 | 敬虔、准确；不用夸张营销语（「爆款」「必看」） |
| 动效 | 极弱：淡入即可；尊重 `prefers-reduced-motion` |
| 声音 | MVP 无背景音乐 |

### 5.1 属灵内容原则

1. **经文正文优先于设计装饰**  
2. 译本标注清楚（默认：和合本）  
3. 不擅自改写圣经原文  
4. 后期 AI 默想必须与经文区分展示，并标注「默想辅助，非圣经正文」

## 6. 扩展性设计原则（不推翻架构）

| 原则 | 落地方式 |
|------|----------|
| 内容与呈现分离 | `Verse` 数据 ≠ `LayoutTemplate` ≠ `VisualTheme` |
| 提供方插件化 | `VerseProvider` 接口；可换 bible-api / helloao / 自建 |
| 生成管道阶段化 | selectVerse → renderBackground → composeText → persist |
| 主题为数据 | 主题 JSON/TS 配置，不写死在组件里 |
| 用户偏好为配置层 | `UserPreferences` 覆盖默认，不改生成核心 |
| 功能开关 | Feature flags（主题包、AI 对话、社群）可远程关 |
| 事件总线式扩展 | 领域事件：`VerseSelected` / `ImageGenerated` / `Shared` 便于埋点与新功能挂钩 |
| API 稳定 | 公开 DTO 版本化（`/v1/verse-of-day`） |

后期加主题：只加 Theme 配置 + 资源。  
后期加译本：实现新 `VerseProvider` 适配器。  
后期加 AI 对话：新模块 `ReflectionService`，读 Verse ID，不碰 ImageComposer 核心。  
后期加社群：新服务与表，消费已生成的 `GeneratedImage` URL。

## 8. 风险与注意事项

### 8.1 神学准确性

| 风险 | 缓解 |
|------|------|
| 译本错误/截断 | 仅使用可信 API；长经文完整换行，禁止意译改写 |
| AI 默想偏离 | MVP 不做 AI 解经；后期需审核词表 + 免责声明 + 人工抽检 |
| 断章取义选题 | 选题策略结合章节上下文；敏感争议议题人工白名单 |

### 8.2 版权

| 风险 | 缓解 |
|------|------|
| 圣经译本版权 | 优先公有领域/明确授权译本；和合本使用需确认地区与条款；helloao / 明确许可源 |
| 字体 | 使用 OFL 字体（思源系列） |
| AI 背景图 | 记录 model、prompt、seed；商用条款合规；避免抄袭名画构图 |
| 用户分享 | 图上标明出处与译本，降低误用 |

### 8.3 图像风格克制

| 风险 | 缓解 |
|------|------|
| 商业/网红风 | 固定负面提示词与风格白名单 |
| 宗教符号滥用 | Prompt 禁止夸张十字架、光环人物脸等 |
| 文字不可读 | Canvas 叠字 + 阴影/半透明底；对比度检查 |
| 成本失控 | 背景可「日级复用模板池」+ 周期性 AI 刷新 |

### 8.4 产品伦理

- 不做成瘾式无限刷新金句  
- 不售卖「代祷排名」等灰色功能  
- 用户数据最小化：MVP 可纯本地

## 9. MVP 范围冻结（开发对齐）

**In scope**

- PWA 前端：今日 / 历史 / 设置 / 分享下载  
- VerseProvider（bible-api.com CUV + 本地 fallback）  
- ImageGenerator（Canvas 叠字 + 预设/可插拔背景）  
- 本地存储（IndexedDB / localStorage）  
- 确定性「每日一句」算法（日期种子）  
- 文档齐全，TypeScript 严格模式  

**Out of scope（本迭代）**

- 真实 AI 绘图 API 账单绑定（先用高质量渐变/图库占位 + Prompt 管道就位）  
- Supabase 账号体系  
- Web Push 生产证书  
- 社群  

---

## 10. 验收标准（MVP）

1. 任意日期打开，今日金句稳定、可复现  
2. 生成 1080×1920 与 1080×1080 PNG，中文清晰  
3. 底部元信息：出处 + 译本 + 日期  
4. 分享/下载在 Chrome Android / Desktop 可用  
5. 历史可回顾至少本次会话与本地持久化记录  
6. 无障碍：主要按钮可键盘聚焦；对比度可接受
